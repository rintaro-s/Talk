# 1ページ
作品名は「Sakura 会話コンポーザー」です。
送信や発話の直前をAIが支える、リアルタイム会話向けのコンポーザーです。
誤字、言い漏れ、沈黙といった「会話中のしまった」を減らすことを目指しています。
チーム名は「緯線（よこせん）」です。

# 2ページ
皆さんも、VC、配信コメント、会議、面接、発表などで、すぐ発言しないといけない経験があると思います。
見直さず送ると、誤字や変な文章が起きます。
逆に毎回見直すのは面倒で、会話の速さについていけません。
対面では発言をCtrl+Zできません。
長い会話では、最初の議論を忘れてしまうこともあります。

# 3ページ
私たちが注目したのは、誤字そのものではありません。
「間違えるくらいなら何も言わない」という選択が起きていることです。
コメントしたくても誤字が怖くて送れない。
会議で一言言いたくても、見直す時間がなくて黙ってしまう。
本当の課題は、こうした参加機会の損失です。

# 4ページ
ターゲットは「言いたいことはあるのに、直前で止まる人」です。
VCでは、誤字や誤読が不安で送信をためらう人です。
会議では、流れを止めずに短い意見や質問を出したい人です。
面接や発表では、沈黙や言い漏れを減らしたい人です。
共通しているのは、本番中に考える時間も見直す時間もないことです。

# 5ページ
既存ツールは「後で助ける」ものが多く、リアルタイム会話には間に合いません。
文章校正は、書いた後に直します。
議事録は、会議が終わった後に役立ちます。
でも、その場で失った発言機会は戻せません。
そこで私たちは、「いま送る・いま話す」の直前にAIを入れます。

# 6ページ
テキスト入力では、ホットキー一発でフローティング窓を呼び出します。
普段通り文章を打ちます。
Enterを押すと、誤字・誤変換・不自然さをAIが校正します。
文体サンプルを使うので、自分らしい口調は残します。
修正文は元のチャットへ貼り付け、必要ならそのまま送信できます。
覚える操作は「呼び出す、打つ、Enter」だけです。

# 7ページ
テキストだけでなく、会話ベースの支援にも対応します。
話に詰まったら、会話の流れとナレッジから次に話す内容をカンペとして出します。
話を忘れたときは、過去の会話を要約して現在の話題につなげます。
終了後には、要約や流れを含む議事録も自動作成します。
音声はSTTで取り込み、速い会話でも支援できるようにしています。

# 8ページ
全体の流れは、文脈理解、入力、AI支援、出力の4段階です。
場面や事前情報を文脈として持ちます。
チャット、音声、資料を入力します。
AIが校正、次の一言、要約、論点整理を行います。
結果を送信、発話補助、議事録として出力します。
重要なのは、操作を増やさず、会話の失敗確率だけを下げることです。

# 9ページ
対談モードは、会話の種類に合わせて支援を切り替えます。
汎用会話では、要約、決定事項、未解決事項、次アクションを整理します。
面接では、候補者の主張、深掘り質問、評価軸、矛盾点を出します。
アイデア出しでは、分類、ツリー化、類似案、次の問いを作ります。
プレゼンでは、現在のトピック、言い漏れ、場つなぎを支援します。
さらにテキストコンポーザーで、送信直前の文章も校正します。

# 10ページ
LLMは、文章生成ではなく「会話助けのエージェント」として使います。
口調やネットスラングは残し、誤字脱字や文脈のずれだけを直します。
3秒止まると次の一言、5秒沈黙すると場つなぎを生成します。
面接、アイデア出し、プレゼンなど、モードごとに判断内容を変えます。
要約や次アクションはJSONで整理してUIに反映します。
AIはローカルLLMと、さくらAI Engineを切り替えて使えます。

# 11ページ
新規性は、AIを「会話の直前」に置いたことです。
校正ツールは文章単体を見ますが、参加機会までは扱いません。
議事録ツールは会議後に役立ちますが、発話中の困りごとは残ります。
この作品は、送信・発話の直前に入り、文体とその場の文脈を同時に見ます。
「会話本番の手前」をAIの主戦場にしたことが特徴です。

# 12ページ
実用性も重視しています。
Windows、macOS、Linux対応のElectronアプリとして提供します。
ホットキーやトレイからすぐ呼び出せます。
タイムアウトやフォールバック、二重起動防止などの信頼性設計も入れています。
貼り付けはOSのコピー＆ペーストを使い、失敗しても修正文はクリップボードに残ります。
会話補助も、音声認識、議事録、外部デバイス連携までMVPで検証しています。
完璧な環境でなくても、最後は手動貼り付けで使えることを重視しています。

# 13ページ
利用シーンは、配信、会議、面接、アイデア出し、プレゼンです。
配信では、誤字を恐れずコメントできます。
会議では、流れを止めず短い意見を出せます。
面接では、深掘り質問や矛盾点を逃しません。
アイデア出しでは、似た案を整理して次の問いにつなげます。
プレゼンでは、言い漏れや場つなぎを補います。
価値は「AIがすごい」ことではなく、「人が会話に戻れる」ことです。

# 14ページ
仕組みには、送信直前コンポーザーと会話支援モードの2つの入口があります。
送信直前コンポーザーは、入力した文章をAIで整えて元のチャットへ戻します。
会話支援モードは、音声や手入力を取り込み、次の一言、要約、深掘り質問を出します。
どちらも同じAIコアを使います。
AIコアでは、文体保持、文脈理解、JSON整理を共通処理します。
入口は2つでも、価値は1つです。
送信・発話・記録の直前にAIが入り、ためらいを参加に変えます。

# 15ページ
審査基準に対しても、機能ではなく価値で説明します。
課題設定は、誤字ではなくリアルタイム参加機会の損失です。
独自性は、校正・会話支援・議事録を「直前支援」で統合したことです。
新規性は、会話本番の手前にAIを置いたことです。
完成度は、ホットキー、設定保存、OS別貼り付け、失敗時フォールバックまで実装したことです。
AI活用では、文体保持、沈黙トリガー、モード別支援、構造化出力を使っています。
実用性は、配信、会議、面接、発表など幅広い場面で使えることです。
「何が作れるか」より、「誰のどんなためらいを減らすか」を伝えます。

# 16ページ
最後に、この作品が目指すのは「誤字も沈黙も恐れずに参加できる」状態です。
AIが会話そのものを奪うのではありません。
人が一歩踏み出す、その直前の瞬間を支えます。
それが「さくらAI会話コンポーザー」です。
